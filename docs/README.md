# JSON / JSONL 磁盘索引：实现与实测

日期：2026-10-18。以下为本机 Windows / Rust release 后端实测，不是界面打开耗时或真实 WebView2 内存验收。

## 当前实现：字符串块扫描与搜索批次

普通 JSON 及 JSONL 超长行后备扫描器增加长字符串块校验和短 ASCII 字符串快速路径，保留逐字节转义处理。扫描直接使用已有 256 KiB 输入缓冲，不构建完整字符串；UTF-8 跨块时只用最多 4 字节补齐一个字符，再恢复块扫描。控制字符、非法 UTF-8、转义和 Unicode 代理对仍需通过校验，块读取继续响应取消与进度。

为避免不同批次负载变化影响结论，以下对照在同一发布模式测试进程中交替运行：`scalar=true` 调用保留的逐字节字符串循环，`scalar=false` 使用当前路径，其他索引流程相同。测试专用开关不编译进正式程序。每种模式运行 3 次，交替先后顺序；样本生成和读回断言不计入打开耗时，没有清空系统文件缓存。数字是后端扫描及建索引耗时，不是 WebView2 界面打开时间。

| 4096 个 ASCII 长字符串 | 33,566,721 | 407.645 ms | 64.241 ms |
| 4096 个中文和表情长字符串 | 33,558,529 | 342.799 ms | 73.992 ms |
| 4096 个转义密集字符串 | 46,149,633 | 397.911 ms | 354.503 ms |

本机负载波动仍明显，转义密集内容继续采用逐字符循环，不对其承诺提速。字符串样本结果不能推广为任意文件的整体加速比例。同轮约 259.3 MiB 的普通 JSON 打开 9,240.766 ms、末页 0.536 ms；JSONL 打开 8,836.386 ms、末页 0.615 ms，单次绝对时间不足以和前几轮判定整体性能变化。索引分别仍为 602,000,048 和 14,000,000 字节。

搜索方面新增 `searchPages` 批次接口，由后端通过 `info.searchBatch` 声明能力：

- 仅合并相邻的小分支，单批最多 8 条路径，每条最多 16 个子节点，合计最多 64 个描述，序列化页内容约不超过 1 MiB。前端保留至多一批额外临时页，嵌套搜索产生新批次时替换旧批次，不加入阅读历史缓存。
- 匹配仍使用 JavaScript 的 `toLowerCase().includes()`，保留 Unicode 行为、深度优先顺序、数组下标起点、隐藏子树与 1000 项结果上限。过大或失败的预取回退到当前分支单页读取，不因未来分支出错而提前中断本来能够返回的结果。
- 取消、关闭或视图改变后不接纳批次响应；返回结果前再次检查文件变化，变化后清理该文档的阅读缓存。取消不会中断已经运行的单批原生 I/O，但不会继续请求下一批。
- 模拟适配器测试中，205 条六字段记录的一次完整搜索，调用数从 208 降到 31（含最后一次文件检查），约减少 85%。这是调用计数测试，不是真实桌面 IPC 耗时基准；原生批次读取行为和限制另由 Rust 测试覆盖。

前端 72 项、后端常规 39 项、6 项发布模式基准与 1 项大文件集成测试通过；JavaScript 语法检查和前端生产构建通过。新增覆盖 1–127 字节小缓冲、真实 256 KiB 边界的 UTF-8 / 转义、非法长字符串、块扫描中途取消、搜索大小约束、JSONL 包装模式、取消和关闭、视图变化、文件变化、Unicode 大小写、隐藏子树、提前截断及失败预取回退。

搜索仍需遍历分页和节点，也仍共享文档锁；超过 8 MiB 的单值全文读取 / 搜索限制未解除。下一步是原生流式搜索及其真实桌面取消、耗时和内存验收。以下保留前几步的历史实现与数据。

实现与边界：

- `.keys` 每项为 8 字节哈希和 4 / 8 字节原始字段序号，按 `(hash, ordinal)` 排序。查询先二分哈希，再读取候选的解码键名，精确比较后定位子节点；哈希碰撞不会返回错误字段。每文档使用带随机种子的哈希状态，索引只在当前会话使用。
- 哈希针对解码后的字符串，因此 `"a"` 与 `"\u0061"` 正确视为同名字段。唯一值路径继续拒绝重复字段；按键定位页面继续选择第一次出现的位置。页面仍按原始字段顺序展示，数值路径段不会误当作数字字符串键。
- `.branches` 记录从 16 字节增至 24 字节，新增键表位置；数组指针为空，不产生键表。紧凑节点仍为 24 / 48 字节；不超过 100 个字段的小对象继续有限线性扫描。
- 建表按 4096 项分块排序，归并最多同时读取 32 个块，不缓存全部字段名或哈希项。源键名使用缓冲读取，内存只保留当前键名；最大原始键名仍为 64 KiB。`key_index.rs` 包含归并和临时文件生命周期管理。
- 排序临时空间另计，最多使用两份按每项 16 字节存储的工作文件。完成、取消、写入失败都会清理自己创建的工作文件，已有同名文件不会被覆盖或删除。新增建表错误直接使打开失败，不会当作 JSONL 坏行跳过。
- JSONL 普通行仍按行解析，不增加字段索引。超过 64 KiB 的长行后备子树共用键表，支持跨行追加和坏行回滚。

验证：前端 67 项、后端常规 36 项通过；5 项发布模式基准与 1 项 32 MiB+ 集成测试另行显式通过。新增覆盖强制哈希碰撞、转义重复键、空键名、UTF-16 转义代理对、原始长度恰为 64 KiB 的键名、两种记录宽度、深层宽对象、超过 32 个排序块的多轮归并、取消及写入失败清理、JSONL 长行回滚。64 位范围仍以编码单测及强制格式小文件验证，未实际生成 4 GiB 文件。

## 前一步：紧凑节点与稀疏宽容器目录

在上一版块缓冲索引基础上，普通 JSON 节点从固定 64 字节改为 24 / 48 字节，子节点 ID 从固定 8 字节改为 4 / 8 字节。使用原有生成器实测，索引合计包含节点文件、子节点位置表和新目录：

| 样本 | 上一版索引合计 | 本轮索引合计 | 减少 |
| --- | ---: | ---: | ---: |
| 200,000 个六字段对象，15,288,891 字节源文件 | 91,200,064 字节 | 34,400,040 字节 | 62.28% |
| 3,500,000 个六字段对象，271,888,891 字节源文件（259.3 MiB） | 1,596,000,064 字节 | 602,000,040 字节（574.1 MiB） | 62.28% |

这仍是逐节点索引；上述大样本的索引约为源文件的 2.21 倍。减少比例依赖字段密度和容器结构，不能推广到所有文件。

实现细节：

- 文件大小小于 `u32::MAX`（4,294,967,295 字节）时，六个字段各占 4 字节，否则各占 8 字节。存储值起点、值长度、子树节点跨度、子节点数、键相对距离，以及合并的键长度与类型。所有缩窄转换检查溢出，文件范围超界时使用 64 位格式。
- 每个节点不再存宽容器指针。仅超过 100 个子节点的容器建立 `.branches` 稀疏目录，每项 16 字节，记录容器 ID 和 `.children` 中的字节偏移；目录按节点 ID 排序，以二分查找定位，内存缓存最多 64 项。子节点页仍一次读取最多 100 个连续 ID。
- 节点块固定为 192 KiB，恰好容纳 8192 个紧凑节点或 4096 个宽节点，避免每次定位都做变长记录除法。扫描和导航不保留完整索引或全部子节点列表。
- JSONL 普通行的 4 / 8 字节行表未改格式；超过 64 KiB 的长行后备路径采用同样的紧凑节点，坏行回滚按当前记录宽度截断。节点、子节点表和目录均随关闭、失败、取消清理；已有同名文件不会被覆盖或误删。旧索引不跨会话复用。

本轮最后一批发布模式基准按单线程顺序执行，没有清空系统文件缓存，也没有测量界面、进程内存峰值或强制刷盘时间：

实现与边界：

- 扫描器不再写入每节点占位记录，只写最终记录。节点按 256 KiB 块合并读写，跨块的父节点回填同样经过缓冲；不会将完整索引或全部子节点列表装入内存。
- 节点记录由 56 字节增至 64 字节，新增子节点位置表指针。第二遍顺序遍历节点，为超过 100 个子节点的容器生成连续的 8 字节子节点 ID 表；读写缓冲各为固定大小。小容器保留有界的链式遍历。
- 宽数组下标与宽容器按页偏移直接寻址，页内最多读取 100 个 ID；描述字段时复用已读节点。对象字段顺序、重复字段拒绝歧义路径的行为保持不变。
- 普通 JSON 的逐节点索引仍大，实测约为上述源文件的 5.9 倍；259.3 MiB 样本的索引约 1.49 GiB。本轮解决打开和偏移分页的 I/O 开销，没有解决普通 JSON 的索引体积。
- 宽对象按字段名查找仍需逐键扫描；字符串仍逐字节校验。上述末页数据针对根容器的偏移分页，不代表宽对象字段路径恢复、全文件搜索或整个界面的响应时间。
- JSONL 普通行仍使用行锚点表；长行后备索引共用本轮缓冲与位置表，包含坏行回滚和关闭清理。索引 I/O 失败直接返回错误，只有 JSON 语法失败才尝试 JSONL。

回归验证：前端 62 项、后端常规 26 项通过；4 项发布模式基准和 1 项 32 MiB+ 集成测试另行显式运行通过。后端新增跨块父节点回填、宽数组晚位置读取、宽对象字段顺序与转义重复键、空容器、越界下标、位置表创建失败及长行坏记录回滚覆盖。长字符串集成样本中，JSON 为 36,012,001 字节，主索引 128,064 字节、位置表 8,000 字节，打开并读末页 134.436 ms；JSONL 为 36,012,000 字节，行表 4,000 字节，同流程 30.129 ms。

同轮 JSONL 复测：20 万行打开中位数 160.749 ms、末页 0.262 ms，索引仍为 800,000 字节；约 259.3 MiB 样本打开 2,772.447 ms、末页 0.309 ms、索引 14,000,000 字节。以下保留前一步的原始实测，数值没有替换。

## 本轮改动

- JSONL 从通用 56 字节节点索引拆出，使用 `jsonl_index.rs`。通过 memchr 查找换行；锚点用 BufWriter 顺序写入，普通行不产生字段节点或回填操作。
- 小于 2 GiB 的文件使用 32 位锚点，否则用 64 位。最高位标识长行子树锚点，普通锚点指向源文件行首。页读取一次取得连续的锚点块，直接定位首行，无需从第一个兄弟节点遍历到末页。
- 每行不超过 64 KiB 时，打开阶段用 serde_json 校验该行；展开时按需解析，并最多保留一个行内解析结果。保留字段顺序；普通 JSONL 行的重复键遵循末值覆盖，与内存模式一致。
- 超过 64 KiB 的行不整行读入内存，而是使用流式通用子树索引，写入独立 `.nodes` 文件。此后备路径不适用每行 4 字节的体积预期；后续已共用上文的块缓冲和宽容器位置表。
- 空行、BOM、CRLF、注释、不合规行跳过、严格模式、首条记录根、原始值根、分页、深层路径、长字符串预览、取消及文件变化检查继续支持。普通行子字段复制可能重新序列化 JSON，保留值语义，不承诺原始空白排版。
- 临时行表和长行后备索引在关闭、失败及取消时清理；进程崩溃残留的启动清理仍未实现。
- JSONL 独立索引这一步没有改变普通 JSON 的语法扫描与节点格式；后续的普通 JSON 优化见本文开头。
- 原生打开流程中的元数据检查和根描述构建移入阻塞工作线程。

尚未优化全文件搜索的前端逐页 IPC 遍历，也未解决预读与前台读取共享文档锁的问题。本轮数据只能说明 JSONL 打开及记录页定位的改进，不能视为全项目所有大文件场景已达标。
