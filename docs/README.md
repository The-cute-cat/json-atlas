# JSON / JSONL 磁盘索引：实现与实测

日期：2026-10-18。以下为本机 Windows / Rust release 后端实测，不是界面打开耗时或真实 WebView2 内存验收。

## 普通 JSON：块缓冲与宽容器位置表

使用根数组包含 200,000 个对象、每个对象 6 个字段的同一合成样本，共 15,288,891 字节。打开包含扫描、写节点索引及构建子节点位置表。前后各运行 3 次，表中为各项中位数；没有清空系统文件缓存。优化后最终一组与前端检查同时运行，因此以该组完整记录为准。

另外实际生成 3,500,000 个对象、271,888,891 字节（约 259.3 MiB）的普通 JSON，单次结果：


实现与边界：

- 扫描器不再写入每节点占位记录，只写最终记录。节点按 256 KiB 块合并读写，跨块的父节点回填同样经过缓冲；不会将完整索引或全部子节点列表装入内存。
- 节点记录由 56 字节增至 64 字节，新增子节点位置表指针。第二遍顺序遍历节点，为超过 100 个子节点的容器生成连续的 8 字节子节点 ID 表；读写缓冲各为固定大小。小容器保留有界的链式遍历。
- 宽数组下标与宽容器按页偏移直接寻址，页内最多读取 100 个 ID；描述字段时复用已读节点。对象字段顺序、重复字段拒绝歧义路径的行为保持不变。
- 普通 JSON 的逐节点索引仍大，实测约为上述源文件的 5.9 倍；259.3 MiB 样本的索引约 1.49 GiB。本轮解决打开和偏移分页的 I/O 开销，没有解决普通 JSON 的索引体积。
- 宽对象按字段名查找仍需逐键扫描；字符串仍逐字节校验。上述末页数据针对根容器的偏移分页，不代表宽对象字段路径恢复、全文件搜索或整个界面的响应时间。
- JSONL 普通行仍使用行锚点表；长行后备索引共用本轮缓冲与位置表，包含坏行回滚和关闭清理。索引 I/O 失败直接返回错误，只有 JSON 语法失败才尝试 JSONL。

回归验证：前端 62 项、后端常规 26 项通过；4 项发布模式基准和 1 项 32 MiB+ 集成测试另行显式运行通过。后端新增跨块父节点回填、宽数组晚位置读取、宽对象字段顺序与转义重复键、空容器、越界下标、位置表创建失败及长行坏记录回滚覆盖。长字符串集成样本中，JSON 为 36,012,001 字节，主索引 128,064 字节、位置表 8,000 字节，打开并读末页 134.436 ms；JSONL 为 36,012,000 字节，行表 4,000 字节，同流程 30.129 ms。

同轮 JSONL 复测：20 万行打开中位数 160.749 ms、末页 0.262 ms，索引仍为 800,000 字节；约 259.3 MiB 样本打开 2,772.447 ms、末页 0.309 ms、索引 14,000,000 字节。以下保留前一步的原始实测，数值没有替换。

## 约 256 MiB 的实际样本

另实测 3,500,000 行、每行同样 6 个字段，共 271,888,890 字节（约 259.3 MiB），并非从小文件线性外推：

```text
source_bytes=271888890 index_bytes=14000000 open_ms=2569.743 first_ms=0.348 last_ms=0.255
```

这是单次本机测量。完整校验仍需遍历每条记录，不能据此承诺所有 256 MiB 文件都能在 0.5 秒内打开；长行、宽对象、嵌套深度、存储介质及系统负载都会影响结果。

## 本轮改动

- JSONL 从通用 56 字节节点索引拆出，使用 `jsonl_index.rs`。通过 memchr 查找换行；锚点用 BufWriter 顺序写入，普通行不产生字段节点或回填操作。
- 小于 2 GiB 的文件使用 32 位锚点，否则用 64 位。最高位标识长行子树锚点，普通锚点指向源文件行首。页读取一次取得连续的锚点块，直接定位首行，无需从第一个兄弟节点遍历到末页。
- 每行不超过 64 KiB 时，打开阶段用 serde_json 校验该行；展开时按需解析，并最多保留一个行内解析结果。保留字段顺序；普通 JSONL 行的重复键遵循末值覆盖，与内存模式一致。
- 超过 64 KiB 的行不整行读入内存，而是使用流式通用子树索引，写入独立 `.nodes` 文件。此后备路径不适用每行 4 字节的体积预期；后续已共用上文的块缓冲和宽容器位置表。
- 空行、BOM、CRLF、注释、不合规行跳过、严格模式、首条记录根、原始值根、分页、深层路径、长字符串预览、取消及文件变化检查继续支持。普通行子字段复制可能重新序列化 JSON，保留值语义，不承诺原始空白排版。
- 临时行表和长行后备索引在关闭、失败及取消时清理；进程崩溃残留的启动清理仍未实现。
- JSONL 独立索引这一步没有改变普通 JSON 的语法扫描与节点格式；后续的普通 JSON 优化见本文开头。
- 原生打开流程中的元数据检查和根描述构建移入阻塞工作线程。

尚未优化全文件搜索的前端逐页 IPC 遍历，也未解决预读与前台读取共享文档锁的问题。本轮数据只能说明 JSONL 打开及记录页定位的改进，不能视为全项目所有大文件场景已达标。
